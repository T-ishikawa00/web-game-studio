## 開始前に必要なこと

現在の `http://127.0.0.1:4394/` はPCのloopback専用で、iPhoneからは開けない。実機へ安全に届ける接続経路は **未準備・未承認**。既存TLS鍵の保管承認は新しいGame005のLAN利用承認ではない。接続方法と期間を別途明示承認した後に、凍結版をそのまま用意して開始する。今はHumanにネットワーク・証明書・ブラウザ設定の変更を求めない。

端末名 / iOS版 / Safari版（分かる範囲）/ 縦持ち画面幅相当 / 低電力モード / 充電中か / 開始時の温度感をメモ。Web表示幅が360〜390px付近の実機で優先確認し、該当機がなければ別幅で実施した事実を残す。模擬viewportを物理端末PASSに数えない。Safariの通常タブで行い、App Store/PWA対応は扱わない。

## Human操作：約6〜8分

1. **標準画質で1分。** 島を回す/拡大縮小し、Galleryを数回開閉。pinch後に誤選択しないか。横送り→候補選択→一覧の展開/縮小。費用・効果・CTAが読め、指で確実に操作でき、島へ戻れるか。Settingsも開閉する。横向きへ一度回して戻し、Safariのバーや画面端で主操作が隠れないかを見る。
2. **建築を一周（約3分が目安）。** 桟橋→作業場→市場→母屋→橋。資金不足は桟橋の出荷で補う。市場は配置を選ぶ。採集・工事・完成feedbackを見て、個別割当なしで最後まで進めるか。急ぐ必要はない。
3. **途中で保存/reloadを1回。** 工事中の資源・建物・工事の状態をメモし、設定で画質を一度切り替えて元へ戻す（各変更時に保存）。保存表示を確認してから閉じてreload。巻き戻り/消失/二重消費がないか。設定の開閉だけでは保存は実行されない。Safariを背景へ10秒→戻る操作も1回。復帰直後に急進行や誤操作がないか。
4. **軽量画質で2分連続。** 設定を軽量へ変更し、島を動かす/Galleryを開閉/出荷する。標準時と比べて引っかかり、入力から反応までの遅れ、読みにくさ、発熱の変化を記録。標準へ戻して見た目が戻るかも確認する。

進行を最初から比較したい場合だけ、SettingsのR3.2進行消去を使用する（この接続先のcandidate保存が対象）。既存のHuman保存を先に消す必要はない。接続先のoriginが変わると保存領域も別になるので、同じURL/originでreloadを確認する。

```text

低電力モード / 充電：
標準：なめらか / 時々引っかかる / 継続して重い

Gallery・CTA・Settings・操作遅延：問題なし / 問題の場面
建築一周：完了 / 止まった場所
保存reload・背景から復帰：正常 / 問題
数分後の発熱：開始と同程度 / 温かい / 強く熱い
fps：未計測 / 計測方法と結果
総合：この端末で継続試遊できる / 修正が必要
```

数値fpsは計測手段がない場合 **未計測** とする。「滑らか」という感覚から60fpsを推定しない。stutterは発生操作と頻度、操作遅延は反応が遅れた対象をメモすればよい。画面録画は任意で、録画自体が性能に影響し得るため有無を記録し、主観操作はまず録画なしで確認する。専用fps overlayや外部計測サービスをBaselineへ追加しない。

判定は実施した機種・OS・画質・時間の範囲に限定する。保存消失、進行不能、繰り返す長い停止、主操作の欠落は修正Gateへ戻す。安全に確認できた場合も全iPhone / 全Safari / App Store適合とはしない。発熱と入力遅延に問題があれば、軽量で改善するかを含めてHuman判断とする。
