## 3. Art Direction — 遊べる小さな箱庭

### 3.1 色替えだけで完了にしない
4層を揃える。
1. 世界: 庭 / ふたりの家 / 配送拠点が文字なしでも見分けられる。
2. 操作対象: 回せる鏡、方向キー、編集可能矢印が固定物と違う。
3. 状態: 光が届く、片方だけ止まる、待機、到着、失敗が見える。
4. 報酬: 花が開く、二人が喜ぶ、拠点が灯るという固有の達成がある。

清潔で丁寧な2Dイラスト、軽い厚みのある机上の箱庭を方向にする。可愛いが幼稚にしすぎない。ルールが読めるトップダウン寄り。背景だけ豪華で駒が無地の四角/emojiという仕上げは不可。大規模3D、自由物理、長いシネマティックは不要。

### 3.2 画面
- 上: 作品名、章/面、現在目標の短文。raw ID/debug値は通常面へ出さない。
- 中: 盤面と対象。装飾は周縁、経路と操作対象は明瞭に。
- 下: 主要操作。光=undo/この面のやり直し、ふたり=方向/undo、配送=出発/停止/調整に戻る。
- 補助: 遊び方、ヒント、音量、面選択。意味不明なアイコン列にせず、短い文字付き。
- 全消去、QA解答再生、debugは内部パネル。通常導線へ混在させない。
- 説明カードで盤面が画面外へ追いやられない。モバイルは優先度で再配置する。

### 3.3 素材
各作品の盤面タイル、主要駒/装置、操作/状態の差分、簡潔な操作図解、実装内容に一致したcoverを用意。全レベル専用イラストは不要。少数の再利用可能な素材で統一感を出す。

Canvas/SVG/画像という手段で品質を決めない。SVGなら形、厚み、素材感、動きまで設計する。「とりあえず図形を置く」だけで終わらない。許可済み環境の画像生成は素材制作の候補にできるが、新しい有料API/契約/認証の作成は不可。利用制約がある場合は未達を隠さず報告。Portalの全画面画像をゲームへ貼り付けない。

可動物、当たり判定、説明文字は実UI。画像へ日英を焼き込まない。生成した操作図と実ルールを一致させる。他作品の素材を転用しない。出所/編集/用途を既存資産台帳へ記録し、権利確認済みを捏造しない。

### 3.4 読みやすさ・動き
- 色だけで対象/目的地/状態を区別せず、形・記号・言葉を併用。
- 主要ボタンは44 CSS px以上のhit areaを内部目標。範囲の重なりで誤操作を増やさない。
- 通常説明は16 CSS px程度から検討。長文を小文字で押し込まない。
- 強い全画面flash、必須の画面揺れはなし。reduced-motion、muteを尊重。
- 矢印キーはゲームへfocusした範囲で扱い、ブラウザ全体の通常操作を奪わない。
- 演出は短く、次へ進む操作を長く封鎖しない。描画と論理計算を分ける。

## 4. 初見UX — 目的→図解→一操作→反応→自力

説明を増やすだけでは今回の問題を解決しない。次の順で教える。
1. 目標を短い一文と小さな前後図で示す。
2. 最初の操作対象を強調し、本人に一操作してもらう。
3. その結果を盤面で確認する。
4. 次の類題ではガイドを外し、理解して使える構成にする。

- 操作説明スライドをNextで送るだけにしない。
- 新ルールは初めて必要になる面で紹介。全ギミックを最初に列挙しない。
- 一度に出す案内は原則一つ。図の位置を対象に結びつけ、操作を覆わない。
- 遊び方はいつでも再表示、skip/閉じる/再開が可能。
- 任意の短いデモは別の小盤面で動かす。実プレイの保存/クリア数/解答を変更しない。
- ガイドを閉じただけで理解済みにしない。表示flagは進行の強制ロックに使わない。
- 初回/再訪/言語切替/undo/幅変更で案内が詰まらない。
- 禁止操作には理由を示す。配送なら「停止してから編集」など。
- **最初の問題が簡単なのは欠陥ではない。今回直すのは説明不足とVisual。**

### ヒント
各面に任意の2段階ヒントを用意。
1. 観点（何から考えるか）
2. 注目箇所/関係（答えを自動適用しない）

ヒントは短い手作り文と図でよく、実行時AIは不要。広告ロック、失敗回数での強制解答、常時正解表示はなし。現盤面に合わない「次の一手」を捏造しない。必要なら初期盤面からの一般ヒントと明記。

### 最初の説明文例
| 作品 | 目標 | 操作 | 重要なルール |
|---|---|---|---|
| 光 | すべての花に光を届けよう / Light every flower. | 鏡をタップして向きを変える / Tap a mirror to turn it. | 一度開いた門は、そのまま / Once opened, a gate stays open. |
| ふたり | ふたりを同時に家へ帰そう / Get both friends home together. | 矢印でふたりが一緒に動く / One arrow moves both friends. | 壁に当たった子だけ止まる / Only the blocked friend stays still. |
| 配送 | ぶつからず全員で配達しよう / Deliver every parcel without a collision. | 道を決めたら「出発」 / Set the arrows, then press Go. | 時計の数だけ待って進む / Wait for the shown number of beats. |

文は意味を維持して自然に改善可。1拍/beatは内部tickのプレイヤー向け表示であり秒ではない。tick、vector等の実装語を説明なしに表示しない。

## 5. 全編構成と制作順

導入6→中盤6→終盤6を目安にする。単調に難しくするだけでなく、新しい理解→自分で使う→少しひねる→達成という波を持たせる。最終面に未説明のルールを追加しない。

内部作業順は **1面のArt/UX完成→中盤代表/最終面の成立確認→学習順の逆算→間の問題→全体QA**。Humanに各段階で承認を取り直す工程ではない。

以下は設計意図。座標・具体的な解答は未検証。Codexが実装し、実ルールで解答/中間状態を検証する。成立しない場合は局所的に修正し、新ルール追加で帳尻を合わせない。

ステージ選択、途中再開、章進行、最終成功画面を用意。試遊では全問へ移動可能な内部導線を残す。Humanが全問解かないと終盤を確認できない状態にしない。

## 6. G001 — ひかりの仕掛け庭 / Lightwork Garden

### 核とArt
一つの光で準備をし、最後に花を灯す。鏡は固定セルの「／」「＼」切替。壁、花、光源、開放保持の門、undoを維持。自由角度・鏡の移動・色混合・燃料・リアル屈折はなし。

Artは**陽だまりの小さな温室**。クリーム色の石枠、低彩度の葉、金属縁の鏡、ガラスの光源。花は受光で開く。鏡の対角線を飾りで隠さない。光は明るいが白飛びさせない。門とスイッチは同じ徽章で結ぶ。固定物を押せるように描かない。最後は温室の灯りが完成する短い演出。

### 導入
L01は前後図→鏡を本人が回す→光が曲がる→花が開く。
L04はスイッチで門が開く→光を外しても閉じないことを安全に確認。Undoは鏡と門の両方を操作前へ戻すと補助説明する。

### 今回の拡張上限
- 門は最大2組。
- L09で**固定分光器を最大1個**導入可。指定入力から光を受け、図示した2出力へ分岐。回転機能なし。指定外からの入射は停止。
- 強度減衰・光の色・干渉はなし。
- 目標花は最大3点程度、可動鏡は原則6個以内。盤面は6×6中心、終盤必要時7×7程度まで。可読性を優先。

## 7. G002 — ふたりの帰り道 / Two Ways Home

### 核とArt
共通入力で独立盤面の二人が一マスずつ動く。壁に当たる側だけ停止。家は通過可能で固定されない。同時帰宅が成功。新床・敵・箱・時間制限は今回なし。

Artは**二つの庭を持つ絵本の見開き**。丸い子と耳/角のある子など、輪郭で区別できる独自の二人。家の徽章も対応。PC左右、スマホ上下を第一案。同じ向き・マス寸法・ラベルの位置を整える。歩く/止まる/先着/同時帰宅を小さなポーズで表現。片方の先着で全体クリアと同じ演出をしない。

### 導入
T01は「1つの矢印→二人」の図と本人の入力。T02は一人だけ壁で止まる状況を明示。T04は「同時に家ならクリア」「着いても次の入力で動く」を前後図と操作で確認。隠れたルールを失敗から察させない。

### 中後半
**同時移動・壁・家だけで深める。** 各4×4〜5×5中心。位置合わせ、壁の利用順、家からいったん離れる、最後の一手の準備を考える。歩数の長さだけを難易度にしない。

### 操作/QA
方向パッドとundoを大きく。WASD/arrow、長押し・連打で意図しない複数手を出さない。両者計算後にgoal判定。両者停止の無意味なundo履歴を増やさない。位置ペアBFS等で全問の解答を検証。最短手数はQA用であり星評価に使わない。片側停止/両側停止/家退出/同時帰宅/undoの独立テスト。二つの盤面を別タブへ分離しない。盤面セルは直接タップしないので、操作ボタン44pxとセル寸法を混同しない。

## 8. G003 — ちいさな配送パズル / Tiny Delivery

### 核とArt
編集→一斉出発→結果確認→設定を残して修正。内部tickで同時移動。二台・各一荷物/一目的地を維持。走行中の反射操作にしない。

Artは**玩具の配送拠点を上から見る盤面**。クリーム/青灰の道、丸みのある二台のロボット、荷物と受取口の対応記号。編集矢印は回転plate、固定矢印はpaint等で区別。待機の残りは時計・数字・ドットで示す。失敗は地点を残し、爆発などで原因を隠さない。最後は配達先が灯る短い達成演出。

### 導入と操作
D01で「矢印を変える→出発→到着」を実操作。D03で別小盤面の同時交差/待機の図解を示し、本問の解答設定は自動適用しない。D04で待機ドットを消費する動きとコマ送りを紹介。

「出発」「停止」「再開」「調整に戻る」を状態に合わせて明示。コマ送りは使えるが初画面で主操作を圧迫しない。失敗後の調整は矢印/待機設定を保持。「全配置を初期へ」「進行を全消去」と混同しない。

### 今回の拡張上限
- 最大二台。三台目、荷物交換、交通AI、新しい優先ルールはなし。
- 可変矢印は原則2〜5か所。有効方向を2方向等に絞ってよいが、選択可能な方向を明示。
- 待機ポイント最大2か所。初期0/1/2拍、必要な後半だけ0〜3拍。
- 待機は到着後n回その場に留まり、その次に動く既存規則を保持。同一訪問で毎tick再発火しない。
- 遠回り、共有通路、二度の交差で深める。道路Editorを作らない。

### 論理/QA
既存の同tick同セル、停止相手侵入、対向辺交換、後続通行、正誤配達先の仕様を維持。原因を具体的な短文で示し地点を強調。pause/step/通常再生で論理結果は同じ。background復帰で経過時間分を一気に進めない。全状態の循環検出/安全上限を維持し、上限超過は成功にしない。正解設定と交差前後の位置/待ち残り/到着順の中間assertを検証。

## 9. 保存・接続・分離

- 既存MVPのgameId/slug、前回追加した実ゲーム用bridgeを維持。旧Connection Lab専用protocolへ戻さない。
- 旧5面は可能な限りルール/IDを保持しArt/ガイドを改善。盤面を変えたらcontent versionを更新。
- 旧保存を無条件に消さない。非互換な途中盤面は元データを保持して安全な再開へ。完了履歴はID対応を検証して維持。新しい問題や説明デモをクリア扱いにしない。
- tutorial/ヒント状態はゲーム別、進行は同一originの日英で共通。
- 保存失敗/未知schema/不正levelは正直に表示。壊れた原データへ自動上書きしない。
- G003の走行途中復元は追加せず、再開は保存された編集状態から。
- origin/source/protocol/gameId/generation/payload検証を維持。古いiframeのmessageを拒否。
- 実広告なし。モック広告は内部QAのみ、通常試遊は広告なし。pauseでデモ/配送tickも停止。
- tutorial/hint/chapterイベントを必要最小限でローカル追加可。外部送信・本番集計はなし。
- 公開0本、Design見本10点を維持。3作品はprototype/full-run-alphaとして既存prototype buildへ。
- 通常/Design出力へprototypeのルート/素材を漏らさない。noindexやリンク隠しだけで隔離と呼ばない。
- Portal Home/Playの再デザインは不可。必要な局所的高さ・接続調整だけ理由と回帰確認を付ける。

## 10. 問題品質の検証

各面にID/version、章、教えること/発見、初期盤面、操作可能箇所、再生可能解答、中間状態assert、反例、2段階ヒントを付ける。

全問の解答を実際のrule functionsへ再生。さらに独立して計算した期待値を持ち、solverとruntimeが同じバグを共有してPASSにならないようにする。実UIでの操作確認も併用。

探索候補: 光=鏡姿勢×門状態、ふたり=位置ペア、配送=矢印候補×待機設定の列挙と決定的simulation。探索に上限を置き、timeoutを「解なし」「唯一解」の証拠にしない。正解手順の再生で言えるのはその解の存在まで。最短/唯一を未検証で断定しない。

修正対象:
- 終盤なのにほぼ何をしても解ける。
- 反転/色替えだけで同じ発見を反復。
- 長い歩行・待機だけで判断が増えない。
- 未説明ルールで失敗させる。
- 意図した終盤の考え方を簡単な抜け道で全部回避できる。

複数解はそれ自体では欠陥ではない。良い別解は認め、想定手順との違いだけで不正解にしない。

## 11. バッチ内部の進め方

1. 既存MVP/QA/path修正を読み、Before・データを保全。
2. 各1面をArt/UXの基準画面として仕上げ、PC/スマホで実ブラウザ確認。
3. 初回ガイドを実入力で確認。
4. 中盤代表と最終面を先に実装して解答検証。
5. 学習順に残りを作り、章・進行・最終成功まで完成。
6. 3作品まとめて回帰QAとVisual/UX自己レビュー、必要修正。
7. 1回のHumanレビューに必要なURL/画像/報告をまとめ、未commitで停止。

各ステップを新たなHuman承認会議にしない。安全/権利/利用モデル制約/根本仕様の矛盾だけ確認。1作品固有の障害がある場合は独立部分を進めてよいが、未完成を完成本数へ入れない。
