## 今回の権限と停止点

- ふたりの導入変更・追加・並べ替えを許可。旧54問／最初の5問維持の制約より学習順改善を優先。ただし共通移動・壁・二人同時帰宅のルールを保持。
- ひかりの問題・判定は保持し、鏡→光路、スイッチ→門、開状態の保持、分光器の入口→二出口を短い形の反応で示す。
- Portal、配送、R5 Visual、直接操作、日英、3表示、保存、Undo、隔離buildを保持。
- stage / commit / push / deploy / 購入 / 外部サービス接続は禁止。前回checkpoint同期の許可を今回へ持ち越さない。
- Human受入は再試遊待ち。新規保存での技術QAは初見ユーザー理解のPASSではない。

## 調査結果と判断

Humanが試したlevelId・表示面番号・保存状態・入力方法は**未特定**。推測で確定しない。旧新規起動はT01、旧保存からはlevelIdに対応する盤面へ再開する。以前の表示番号は配列順から算出し、保存は既にIDとversionを使用していた。

T02は初手の有効方向が3通りあり、最短の手順は家から遠ざかる左移動から始まる。T03は最低8回の片側調整、T05は最低11回。T06は4手と短いが片側調整が3回必要であり、手数だけでは導入向けと判断しない。問題順に学習上の段差があることと、Humanの実際のつまずき原因は別の事実として扱う。

## ID・version・保存

旧T01〜T18のオブジェクト、盤面、version、解答・ヒント・中間状態を変更していない。新規問題のみ新ID T19〜T21とversion 1、別の解答・中間状態を追加。内容を変えた既存IDはないため既存versionの更新／データ移行は不要。

実行順は `home-levels-learning.ts`。面一覧の操作も `level:T03` のようにIDで解決し、表示番号を保存の識別子にしない。旧T03途中は表示10へ、旧T04は表示11へ、旧T05は表示12へ移るが、同じ盤面の同じ位置を復元する。旧18クリアはそのまま18クリアで、新規3問を無断でクリア扱いしない。既存利用者を強制的に01へ戻さず、面一覧で導入を選べる。Undoは従来どおり現在の再開後の操作を対象とする。

## ひかりの表示契約

`light-cause.ts` は実際のtrace結果から門が開く前後の段階を再構成する表示専用処理。engine / level / 判定 / saveを変更しない。`light-feedback.ts` は前の光路を短く退かせ、反射後の光、入口からの二枝、スイッチの輪、門の閉→開、到達後の開花を順に描く。

入口の描画100ms→枝は110ms後に開始し100ms描画→スイッチ反応215ms→門245msから45msで開く→次の段階300ms。通常の反応は約290ms、門連鎖でも最大約890ms。毎手の待機や入力lockはない。光を外しても開いた門はチェックと短い輪・「開いたまま」で確認できる。

連続入力は前の描画を取り消し、直近の実状態だけを示す。Undo、Menu、表示切替、外側viewport変更、pagehideで古い描画を破棄する。案内消去によるiframe内部の高さ調整だけで、新しい描画を誤って取り消さない。reduced-motionではこの補助演出を省く。結果・保存・timerはanimationendを待たない。
