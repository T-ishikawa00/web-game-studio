## 2. 画面の完成像：ボタンの消去ではなく、主操作の移動

### 3作品共通の優先順位
1. **盤面・操作対象・目的。** 初見で「何を触るか」が分かる。
2. **現在の結果。** 光、二人の動き、配送、失敗地点を読める。
3. **小さな補助操作。** Undoとメニューを盤面の外縁に固定し、必要なときすぐ使える。
4. **状態に応じた行動。** 配送の出発／停止や、クリア後の次へだけを適切に見せる。

### デザインの制約
- 盤面下に、旧コントロールバーと新しい小型UIを重複表示しない。
- 空いたボタン領域を、不要な空白や大きな説明カードで埋め直さない。盤面・二画面比較・撮影構図へ還元する。
- 盤面のマスに補助UIを重ねて、鏡・門・家・時計・配送先を隠さない。盤面に接した外側の浅い領域を使う。
- 小さな見た目でも、主要な補助ボタンの実hit areaは44×44 CSS px以上を内部目標とする。透明な領域同士や盤面マスと重ねて水増ししない。
- Undoは短い文字と統一アイコン、メニューも意味が分かる表示を基本とする。初見ユーザーへ意味不明な記号だけを渡さない。Hover時の説明だけでは済ませない。
- R3のコントラスト、focus-visible、押下反応、disabledを維持。ボタンを小さくするために文字を極小・極薄にしない。
- 物理スマホに見える画像や撮影画像だけで「押しやすい」と合格扱いしない。

### 共通の補助操作
| 操作 | 通常プレイでの表示・意味 |
|---|---|
| 1手戻す / Undo | 対応済み作品で盤面外縁の定位置へ。一回で既存の一手を戻す。メニュー深部へ隠さない。履歴なしは位置を保って無効にする |
| メニュー / Menu | 遊び方・ヒント・面一覧・設定・やり直すへの入口。大型ツールバーにはしない |
| やり直す / Restart | 原則メニュー内。現在の面の試行だけを初期化。全体のクリア履歴を消さない。変更済みの試行を捨てる場合は既存の確認を維持 |
| 次へ / Next | クリア後だけ表示。花が咲く／二人が帰る／荷物が届く演出を遮らない。自動遷移せず、新しい明示操作で進む |
| 全データ削除 | 既存の別管理領域を維持。プレイ用のRestartと統合しない |

Undo対象のない作品・phaseに統一感のためだけのUndo機能を新設しない。既存の機能を確認して残す。

## 3. Lightwork Garden — 鏡を直接タップして遊ぶ

### 主操作
- **PC: 鏡をクリック。タッチ: 鏡をタップ。** 一回の操作で、既存ルール通り一回だけ向きを変える。
- 既に直接操作できている場合、別の入力ハンドラーを足さず、既存経路を整理して使う。
- 鏡の配置移動、自由な角度指定、ドラッグによる新しい解法は追加しない。
- 固定物・花・門を押して鏡と同じ反応をさせない。回せる対象の輪郭／軽い反応で区別する。
- 押した場所を短く示し、光路・門・花は実engineの結果を表示する。演出用の偽成功・自動解答はしない。

### 画面
- 解答中の大きい操作バーを撤去。小さなUndo＋メニューを残す。
- 光源から全目標までを見せ、写真映えのための切取りやマスの変形をしない。
- クリア後にNextを表示。最後の面は既存の全編終了導線を維持。

### 教え方
初回は、目的「すべての花に光を届けよう」＋対象鏡の近くの短い案内「鏡をタップして回そう」。PCで必要なら「クリックして回そう」とする。

図解は再利用するが、大きな説明カードを必須の前置きにしない。実際に本人が鏡を回したことを確認して案内を進める。光路・門保持・分光器などの既存ルール説明は削除せず、該当する面で短く示し、詳しい図は遊び方から再表示できる。

## 4. Two Ways Home — 共通スワイプ／方向ドラッグを追加

### 主操作の契約
- **タッチ: どちらかの盤面上を上下左右へスワイプ。** 二人に同じ方向を一回送る。
- **PC: 矢印キー／WASDを維持。** マウスの主ボタンによる盤面上の短い方向ドラッグでも同じ操作を行えるようにする。
- **一回のスワイプ／ドラッグ＝最大一手。** 長く引いても何マスも動かさない。
- キャラクターだけをつかんで移動する操作ではない。どちらの盤面から始めても二人への共通入力。一人だけ動かす新モードやクリック先までの自動経路探索は作らない。
- 縦で上下、横で左右に並んでも、盤面内部の上下左右は変えない。

### 入力判定
既存ライブラリ追加なしの小さな入力変換を基本とし、次を明確にする。

1. 有効な開始位置は、どちらかの盤面の入力領域。説明、メニュー、Undo、D-pad、余白から始まった動作を方向入力にしない。
2. 一つのprimary pointerを追跡。開始時には盤面を動かさない。離したときに有効な方向だけ一回確定する。
3. 静止タップやわずかな手ぶれは移動にしない。距離しきい値は表示CSS座標で扱い、例として20 CSS px程度から実操作で調整する。値は内部定数として記録し、毎面違う設定にしない。
4. 横／縦の優勢が十分な場合だけ四方向へ確定する。ほぼ斜めの曖昧な動作を無理に移動へ変換しない。優勢比1.3程度を初期候補にしてよい。速度や厳密な直線軌跡を条件にしない。
5. pointercancel、複数指、Escape、開始した盤面の外でのrelease、pagehide、mode切替、該当領域のresize、メニュー開始では未確定gestureをキャンセルする。途中状態を次のgestureへ持ち越さない。
6. 手を離す前に開始位置付近へ戻した場合も、最終変位がしきい値未満なら無操作。
7. pointerupとその後のclick、touchイベントとの二重登録により二手入らないようにする。pointerごとの処理と確定済みフラグを最小限に使う。
8. 判定結果は既存のmove(direction)相当のコマンドへ渡す。別の移動／衝突／勝利／履歴ロジックを書かない。
9. 両者とも壁で動けない場合の一手・履歴の扱いは、既存engineの仕様を維持。方向入力の受付と、実際に位置が変わったことは区別する。
10. 連続入力のため無制限キューを作らない。描画が追いつかない連打で飛び越し・二重歩行が起きないよう既存の入力抑制と整合させる。

値は調整可能な実装初期値であり、Humanへの数値ごとの再確認は不要。最終値と、短い／ゆっくり／斜め／長い入力の挙動を報告する。

### D-padは削除せず、選べる補助操作へ
- 初期の主表示では大きな十字キーを常設しない。
- 最初の入力案内に「方向ボタンで操作 / Use direction buttons」というクリック／タップ可能な小さな入口を必ず用意する。スワイプができないと入口へ辿り着けない構成は禁止。
- 案内を閉じた後も、メニュー／遊び方から少ない操作でON/OFFできる。選んだ後は、四つのnative buttonで全54問中この作品の全18問を操作できること。
- ユーザーがD-padをONにしたら、通常／縦／横への切替で勝手にOFFにしない。ON時は占有領域を確保して盤面を覆わない。
- OFF時のbuttonは透明にして残すのではなく、フォーカスとポインター対象から除く。OFF操作後のフォーカス先を確保する。
- 設定保存は既存の表示設定方式を優先。ゲーム進行schemaに混ぜず、storage不可ならメモリ上でも切替可能にする。
- キーボードを用意しただけで、スワイプの代替を完了扱いにしない。

### 教え方・フィードバック
「どちらの庭をスワイプしても、ふたりが動く」を、短い一回の方向表示で教える。キャラクターを個別に引っ張るイラストは使わない。

チュートリアルの完了は本人の有効操作で判定。壁で無変化の入力だけで「移動を理解した」と進めず、その場で短い次の案内を出す。壁で片方を止めること、片方だけ帰宅してもクリアではないことを維持する。

撮影でも使える小さな方向マーカーを、実際の受付入力に応じて短く表示してよい。手の軌跡を画面全体へ常時出さず、障害物の関係を隠さない。

## 5. Tiny Delivery — 盤面編集を直接化し、実行だけ残す

### 盤面編集
- 編集可能な矢印を直接クリック／タップして、既存の許可方向へ一段だけ切り替える。固定の道は変更しない。
- 待機は、対応する盤面上の時計をクリック／タップして調整する。今の有効な値の集合を使い、範囲・tickの意味を変えない。
- 時計の近くに小さな離散値選択を出す方式を基本に、現在値と設定可能値を示す。右端／最下部でも画面外にはみ出さない。必要なら短い下部の設定行へ逃がすが、大型の常設設定パネルには戻さない。
- popupのクリックが背後の矢印回転／出発へ伝播しないこと。閉じるだけなら値を変えない。一回の変更は既存履歴に一回だけ反映する。
- 走行／失敗／クリア等で編集不可なら実際に無効にする。外観だけ編集可能に見せない。

### 実行操作は見える状態で残す
| phase | 主操作 | 補助操作 |
|---|---|---|
| 編集 | ▶ 出発 / Go | メニュー、必要な編集補助 |
| 走行 | 一時停止 / Pause | 必要な場合に調整へ戻る入口 |
| 一時停止 | 再開 / Resume | 1コマ / Step と調整に戻るをコンパクトに提示 |
| 失敗 | 調整に戻る / Edit route | 衝突地点と理由を保持 |
| クリア | 次へ / Next | 必要なら再試行／面一覧 |

- 盤面のすぐ外に、小さな明確な主操作を一つ置く。巨大なバー、無効button群の常設はしない。
- ロボットそのもののtapを隠れた出発操作にしない。編集のたびに自動出発させない。
- 「調整に戻る」は経路・待機設定を保持して試行開始位置へ戻す。初期配置のresetは別操作としてメニュー内に残す。
- Stepは停止中のみ。一回で論理1tick。経路編集時・走行時は常設無効ボタンとして主張させない。
- 主操作の見た目がGo→Pause→Resumeと変わっても、hit areaと位置を安定させる。表示直後に前のpointerupで新しいNextやGoが発火しないよう、入力トランザクションを分ける。

### 教え方
「矢印をタップして道を変える」→本人が編集→「道ができたら出発」。実際の正誤判定をしない段階で「正しい道が完成」と偽って案内しない。待機設定は初登場の面で該当時計と結びつけて説明する。

## 6. チュートリアル・アクセシビリティ：隠した操作を覚えさせない

- 大きな常設説明カードを、初回の短い目的文＋対象付近の一手案内へ置き換える。詳しいR2/R3の図解・段階ヒントは遊び方／ヒントから再利用する。
- 最初の画面を大きなmodalで塞ぎ、何回もNextを押さないと盤面へ触れない構造は禁止。案内は閉じる／再表示ができる。
- 案内の吹き出しは操作対象を覆わず、実操作は本人に任せる。デモでengineの解答やクリア履歴を進めない。
- 保存済みの利用者に全チュートリアルをやり直させない。入力方式が変わった「ふたり」では短い新操作案内を必要に応じて出せるが、進行・ヒント・旧保存を初期化しない。
- PC／タッチ／D-pad選択時に説明が矛盾しないこと。User Agentだけで入力方式を固定せず、実際の入力と明示選択を尊重する。
- native button・適切な名前・キーボードfocusを優先する。Canvas等なら、既存のアクセシブルな操作層を保全する。画像だけのクリック領域へ退化させない。
- game focus外、input/select/contenteditable、メニュー・dialogの操作中に矢印/WASD/Spaceを横取りしない。Spaceでボタンを押してゲーム移動も発火する構成は禁止。
- Menu/Helpの開閉、Escape、フォーカス復帰、背景入力抑止を検証する。既存のmodalとmodelessを混同しない。
- reduced-motion・muteを維持。派手な点滅や、操作方法を長押し・二本指gestureだけに隠す仕様は追加しない。

## 7. Pointer／スクロール／拡大の安全設計

### 入力の一元化
Pointer Events等を既存構造に沿って利用する。押下は視覚feedback、確定はrelease／clickという最小の流れを基本とし、既存action handlerに一回だけ渡す。全ゲームを書き換える入力フレームワークは不要。

### tapとswipeを混ぜない
- 鏡／配送の編集はtap。押した位置と離した位置が別の対象、スクロールに移行、キャンセル、多指になった場合は編集を実行しない。
- 「ふたり」のswipeは専用の盤面入力領域だけ。Undo/Menu/時計選択/面選択を触っているときにゲーム入力へ変換しない。
- pointer captureを使う場合、release・cancel・lost capture・mode変更で片付ける。入力確定後のlost captureで二度確定しない。
- OS／ブラウザによるキャンセル、境界外release、未完了gestureを受けたら無操作で安全に戻す。秘密のショートカットにしない。

### ブラウザ操作との競合
- ページ全体へ `touch-action:none`、全域preventDefault、拡大禁止viewportを指定しない。
- 鏡／配送のtap主体領域では、不要なスクロール抑止を増やさない。
- 「ふたり」の方向gestureは盤面上に限定してブラウザpanとの競合を制御する。`touch-action`の適用対象は実際に触る要素と必要な祖先まで確認し、gesture中に設定を変えて解決したつもりにしない。
- 複数指はゲーム移動としては処理しない。ブラウザのpinch zoomを妨げない設定を優先し、ズームでcancelされた場合も移動を残さない。親要素側の設定でzoomを止めていないかも確認する。
- ゲーム領域外からはページscroll、help内ではhelpのscrollができること。狭い画面でD-padを使う選択肢も残す。
- 入れ子iframe・実container・DPR・CSS scale・scroll offset・縦横切替後の座標を検証。見た目の鏡と実際のhit areaが一致しなければ不合格。

## 8. 通常／縦9:16／横16:9への統合

R3の3表示を維持し、今回の軽いUIを**すべてのmode**へ適用する。通常表示だけ旧ボタン列が残る改修は禁止。

### 構図
- ひかり: 光路の全体と目標を主役。外縁に小さなUndo/Menu。未クリアのNextは置かない。
- ふたり: portraitは上下、landscapeは左右。両盤面を同時に表示する。どちらからの入力も共通。D-pad OFFの空き領域は二面の表示へ還元する。
- 配送: 盤面と配達／待機状態を主役。必要なphaseの主操作だけ残す。
- 撮影の目的表示・面番号は短く。長い章タブ、常設説明カード、内部QA、レビュー画面は撮影枠に入れない。
- 安全ガイド／字幕余白が既存実装にあれば維持。特定SNSのUI被りを全端末で保証したとは言わない。
- 撮影モードの出口と設定はクリック／キーボードで必ず辿れる。入力手段を消して「撮るだけで遊べない」表示にしない。

### 状態
- mode切替、D-pad表示切替、Menu開閉のためにiframeやengineを再生成しないことを基本とする。
- levelId、配置、門、二人の位置、配送経路／待機／tick、Undo、クリア記録、ヒントを保持する。
- gesture途中でmodeを変える場合は**未確定gestureのみキャンセル**。直前までの有効な手は消さない。
- 配送の走行中は既存R3の安全な境界で停止して切替え、明示Resumeまで進めない。複数の停止理由がある場合は、設定を閉じただけで広告／非表示等の停止を解除しない。
- 同じページ内の表示変更と、URL直リンクへの再読込を区別する。再読込時は既存save restore仕様であり、未保存Undoまで永続化する新要件にはしない。
- input表示設定はゲーム進行と分離する。保存不可でもプレイでき、他作品の進行へ干渉しない。

## 9. 未判定Secret候補は別トラックで扱う

R3報告では、全件検査で `.tmp/r3-before/manifest.json` の候補1件（画面上のruleは `generic-api-key`）がHuman判定待ち。**一時ファイルという理由で誤検出・無害とは断定しない。**

今回認めるのは、値を表示しないローカル調査と、安全な根拠報告まで。

1. 実際のscanner結果で、file／rule／行／JSONのkey・生成処理を確認。値、値を含む行全文、部分文字列を回答・スクショ・新ログへ出さない。
2. manifest作成処理と同じ世代の入力ファイルを調べる。ハッシュ記録の疑いなら、対応する**同じbytes**から計算して候補値とメモリ内で照合する。R4で変更後のファイルを使って誤った不一致判定をしない。
3. 報告するのは、生成元の種類、照合方法、合否、秘密情報かどうかの推奨分類と残る不確実性。値そのものは、ハッシュ候補であっても転載しない。
4. `.tmp`一括除外、rule丸ごと無効化、広いallowlist、候補削除でのPASS化、既存例外の拡張はしない。生成物の再作成で証拠を上書きしない。
5. Secret Scanの状態を、実装QAから分離する。「実装QA PASS／Security候補1件PENDING」のように報告し、全体Security PASSとは書かない。
6. 値を外部providerへ送って検証しない。実credentialの疑いが強い／今回の出力に混入する可能性がある場合は、その関連処理を停止してHumanへ安全に報告。自動revoke・登録・履歴書換えはしない。

候補の判定待ちは、安全性に影響しないUI改修まで形式的に止める理由にはしない。ただし疑わしい値の利用・拡散を伴う作業は進めない。解決しても今回commit/pushの権限はない。

## 10. 一括実装の進め方

1. ローカルR3を保全し、3作品の直接操作済み箇所／旧button処理／tutorial／mode切替を確認。
2. 既存actionへ接続する入力経路と、状態別に残すUIを小さく整理。「ふたり」のswipeとD-pad代替を先に成立させ、イベント衝突を確認。
3. ひかりと配送はtapを活かし、常設バー・説明の配置を整理。配送の時計設定を直接操作へ接続。
4. 3表示・日英へ統合し、導入／中盤／終盤の実画面で目視・操作して修正。
5. ルール保全・全54問の既知解答・追加入力テスト・保存／停止／モード・build隔離・Securityを検証。
6. 一つのレビュー資料へまとめ、Humanレビュー待ちで停止。

色一個、button一個、一作品ごとの確認で止まらない。可逆な細部は主担当が判断して進める。重大な仕様衝突、安全性、権限、必要資源の不足だけを一括で質問する。工程が進んだことだけを理由に品質を下げない。

## 11. QA・受入基準

### 11.1 既存の保全
- 開始時と終了時で全54問、ルール、Artを比較。入力経路以外のsemantic変更を混ぜない。
- 現engineで全54問の既知解答と既存の中間assertを自動再生する。全問×全mode×全言語を、人間の全通し試遊と称して繰り返す必要はない。
- 通常／Design／prototypeのbuildと隔離、Portal・旧fixture、セーブ失敗・破損データ保持・reset対象範囲・モック広告を確認。
- 空白パス再発防止とrepo包含検査、diff、secret scanを実施。stageを作って検査しない。stagedが空でも作業ツリーを検査する。

### 11.2 入力と誤操作防止
| 対象 | 必須ケース |
|---|---|
| ひかり | mirror tap/click/keyboardが各一回だけ回転。drag-off・cancel・固定物tapは無操作。門を開いた後のUndoを維持 |
| ふたり | 上下左右で二人へ同じ一入力。片方だけ壁、両方壁、片方帰宅、両方帰宅、Undo。長いswipeも最大一手 |
| gesture境界 | 静止tap、手ぶれ、斜め、ゆっくり動作、開始位置へ戻す、盤面外release、多指、pointercancel、lost capture、Escape、pagehideで誤入力なし |
| click重複 | pointerup後のclick、Enter/Space、keyboard repeat、D-pad操作が二重の手にならない |
| 代替操作 | swipeなしでD-pad表示へ辿れる。D-padのclick/tapだけで全種類の操作が可能。ON/OFF・focus・mode移動が安全 |
| 配送 | 矢印の一段変更、時計の許可値、popup外閉じ、非編集phaseの編集拒否、Go/Pause/Resume/Step/失敗/Edit route/clear |
| 結果と破棄 | Restartの確認cancel、面移動、Nextの初回クリック、全編最終面。Edit routeが編集内容を消さない |
| input非対象 | メニュー／説明／フォーム／Portal上の入力がゲームへ伝播しない。盤面外scrollとブラウザ拡大を壊さない |

新しい入力は実ブラウザでpointer/touch/keyboardから操作する。engine関数を直接呼んだテストだけで「タッチ操作PASS」としない。ブラウザのtouch emulationと物理端末を区別する。

### 11.3 モードと保存
- 3作品×通常／縦／横、日英で導入と密度の高い最終面を確認。旧バーの残存、盤面の欠け、操作座標のずれ、英語のはみ出しを確認する。
- 開始目安: 通常1440×900、390×844、360×800、狭幅320px。撮影枠はR3の有効サイズを維持して検証。小画面に不適切な撮影枠を強制しない。
- Two Ways Homeの上下二面は常に同時表示。D-pad ONでも盤面がボタンの下へ隠れない。
- Auto→Portrait→Landscape→Auto、D-pad ON/OFF、gesture途中の切替で状態とUndoを確認。
- 配送走行中の切替・メニュー・模擬広告・pagehideの停止復帰を確認。時計設定中にresizeしても背後の操作は入らない。
- 保存に失敗した場合も入力を妨げず、保存成功の偽表示をしない。R3以前のsaveは互換性維持。

### 11.4 Visual/UXの自己レビュー
合格像は「buttonが小さくなった」ではなく、次を満たすこと。
- 初回、何を触ればよいかが画面から分かる。操作を探すための適当な連打を要求しない。
- 解答中は盤面が主役。大きな常設バー、無効操作の列、長い説明の常設がない。
- Undoとメニューが探せる。配送の出発は隠れていない。D-padの代替も見つかる。
- 縦動画で光・二人・配送の変化が追える。必要なときは実入力の短い方向表示が理解を補う。
- Artの気に入られている部分は残っている。UI削減を理由に無機質な全画面へ変えない。

物理スマホ、未実施ブラウザ、投稿後の字幕/UI干渉、初見ユーザーの理解、集客効果は、実測していなければNOT TESTED。Human Acceptanceやアクセシビリティ適合認証を自己付与しない。

## 13. 停止位置

**3作品を一括で実装・自己修正・QAし、最後のHumanレビュー待ちで停止する。**
