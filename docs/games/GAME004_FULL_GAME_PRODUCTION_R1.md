## 4形態 / 4モジュール

1 Runの選択は4回（module→機体→module→最終形態）。同じmoduleの重複は禁止。12枠を埋める目的で追加しない。

|最終形態|操作差 / 代償|
|---|---|
|SWARM / CYCLONE|30片の広い一斉射出。近い盾を開く。距離と広がりを選ぶ|
|SWARM / SATELLITE|4片を射出から残して防御に使う。被弾ごとに1片散逸し2秒回収不可。攻撃に回る片数を減らす|
|LANCE / RETURN|細い高速射線・4体貫通・自動再回収。列を作って繰返し撃つ|
|LANCE / FOUNDRY|3片を重い単発へ束ねる。正面装甲に強いが、貫通と自動回収を失う|

|module|役割|組合せ例|
|---|---|---|
|FIELD|押している間の回収半径+100|SATELLITEの防御用金属を集めやすくする|
|BRAKE|射出時の自機反動を消す|細いLANCE射線の位置を保つ|
|DRIVE|装甲回収後1.8秒移動補助|支援破壊→側面へ移動|
|SHOCK|近い通常機を射出時に押す。Boss対象外|回収直後の退路を作る|

6種類のmoduleペア×4形態×3作戦でcheckpoint整合をunit検証。全72組のHuman難度/優劣評価を実施した意味ではない。自動入力での複数形態完走と固有mechanic検証はReview参照。

## 保存と継続

`tinlumo.game004.magnet.full.v1` / schema1 / content `magnet-full-r1`。localStorageの単一envelopeへ設定・解放・clear回数・最短時間・形態・区画開始checkpointを一括保存。server・telemetry・個人情報なし。

- clear時に記録と次作戦解放をatomic更新しcheckpointを消す。失敗時もcheckpointを消し、Retryは作戦の最初から。
- checkpointは区画開始だけ。選択済み機体/module/形態、HP、累積時間、seed、回収/repair進捗、片の種類・充電・保持/防御属性と正規化開始位置を保持。飛翔軌道、速度、particle、音、敵の途中animationは保存しない。敵は区画開始配置、飛翔片は安全なloose状態へ再配置。
- 再開後は最初の操作まで時計を止める。選択画面途中の再読込は当該区画開始へ戻る。正常clear前の成績巻き戻しはこのcheckpoint方式の仕様。
- 書込後readback確認。拒否・容量不足・破損・未知version・別タブ競合を保存成功と表示しない。壊れた原文は自動削除せず、当該タブのmemory進行は可能。
- 他タブの更新を検知したら上書きを止める。resetは確認後にこのkeyだけ。成功時は進行中runも破棄してAへ戻す。別ゲームkey不変。
- JA/EN、音、軽減設定を保存。端末の軽減設定は初回defaultにだけ採用し、明示したOFFを次回上書きしない。
