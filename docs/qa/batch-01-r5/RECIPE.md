# R5 素材規則と制作レシピ

実物の正本は `src/prototypes/art.ts`、`visual-language.ts`、`game-r5.css`。比較は REVIEW.html、実素材の60／40／32px表示は MATERIALS.html。新しい管理基盤や画像APIは使わない。

## 素材と状態の契約

- SVGは1マス60×60、中央anchor。キャラ／車体の本体は50-unit、約83%。3-unit輪郭を含め約88%。隣のセルの判定は変更しない。
- ○の子は丸角・縦長の目、◇の子は切欠き角・非対称の目。対応する家とHUDも同じ紋章。車体／受取口も○と◇で結ぶ。家・受取口に顔を付けない。
- つぼみ→5枚の花弁、閉門→空いた通路、帰宅→外周とHUD、配達→受取口の荷物とチェック。いずれもengineの実状態から描く。
- 60／40／32 CSS pxで形・顔・向き・紋章を確認する。表示用のA/B置換では、英語の冠詞Aを変更しない。Helpは実素材と同じmasterを使う。
- 固定矢印は床の印、編集矢印は枠つきplate。時計と重なるマスでは上55%が矢印、下30%が時計、3%の間隔。単独対象はセル内88%。補助ボタンは44px以上。細かい盤面セルを一律44pxへ拡大しない。

## 次作での短い手順

1. 最大密度の実盤面を選び、背景／床／固定物／操作物／目標の5役を塗り分ける。図形masterを作り、既存座標のrendererへ接続する。
2. 目標の形変化と、主役の輪郭・占有率を先に決める。静止画だけでなく、本人の入力→engine結果を実ブラウザで見る。
3. 常設HUDは面番号と達成記号へ。初回は1つのcueと短文、1操作後は退く。Help・ヒント・保存異常・安全な初期化の文は保持。再表示は表示専用stateで扱う。
4. 演出は確定後の描画層だけ。移動150ms、押下変位1px、実swipe後の方向cue350ms。animationendで勝敗やtickを進めない。reduced-motionでは移動演出を省く。
5. 通常は端末幅優先。縦は二面上下、横は左右。9:16は432×768、16:9は960×540 CSS pxで検証し、小幅の撮影モードでは通常へ戻れることを確認する。
6. 同条件Before/After、全問解答再生、入力境界・保存・停止・隔離を確認。素材シートと短い実操作動画を残し、Humanの理解・楽しさ・実機受入を別Gateにする。

共有できるものは寸法、輪郭、対応紋章、短いcue、状態契約。作品ごとの主役・壁の色／外縁、目標の形を機械的に流用しない。今回の比較では、葉の反復・厚い外枠・常設文章を減らし、盤面と操作物へ表示面積を戻した。
